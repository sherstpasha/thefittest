# ТЗ эксперимента по подбору гиперпараметров

Реализовать воспроизводимый эксперимент сравнения методов поиска гиперпараметров
на 30 задачах и пяти семействах Pipeline для каждой задачи.

## Наборы задач

В эксперимент включаются 30 задач: 11 задач классификации и 19 задач регрессии с одной целевой переменной.

### Классификация — 11 задач

Источник: `thefittest.benchmarks`.

1. `BanknoteDataset`
2. `BreastCancerDataset`
3. `CreditRiskDataset`
4. `DigitsDataset`
5. `IrisDataset`
6. `UserKnowladgeDataset`
7. `WineDataset`
8. `TwoNormDataset`
9. `RingNormDataset`
10. `TextureDataset`
11. `AdultCensusDataset`

### Регрессия — 19 задач

| Задачи | Источник | Количество |
|---|---|---:|
| F1–F17, каждая функция отдельно | `thefittest.benchmarks.symbolicregression17` | 17 |
| CombinedCycle | `thefittest.benchmarks.CombinedCycleDataset` | 1 |
| Diabetes | `sklearn.datasets.load_diabetes` | 1 |

Данные используются полностью; ограничение числа объектов задаётся только через `--max-samples`.
Для F1–F17 по умолчанию генерируются 1 500 равномерных точек в границах `problems_dict`, без шума.
Seed генерации функции Fi равен `data_seed+i`, по умолчанию `data_seed=42`.
`--noise` задаёт стандартное отклонение гауссовского шума как долю стандартного отклонения сигнала.
Число точек задаётся через `--samples`; сгенерированные данные сохраняются до начала поиска.

Точные повторные строки `(X, y)` удаляются с сохранением первого вхождения.
Если после этого остаются одинаковые X с разными y, такие строки объединяются в группы:
для тестового разбиения используется `GroupShuffleSplit`, для CV — `StratifiedGroupKFold`
в классификации и `GroupKFold` в регрессии. Группы не пересекаются между обучением и проверкой.
То же правило применяется к внутренней CV stacking.

## Модели и пространства поиска

Каждая задача решается пятью семействами Pipeline своего типа: всего 150 пар «задача × семейство».

| Семейство | Классификация | Комбинаций, до | Регрессия | Комбинаций, до |
|---|---|---:|---|---:|
| SVM | `SVC` | 393 216 | `SVR` | 393 216 |
| Случайный лес | `RandomForestClassifier` | 829 440 | `RandomForestRegressor` | 414 720 |
| Гистограммный бустинг | `HistGradientBoostingClassifier` | 829 440 | `HistGradientBoostingRegressor` | 829 440 |
| Нейронная сеть | `MLPClassifier` | 442 368 | `MLPRegressor` | 442 368 |
| Stacking | `StackingClassifier` | 167 936 | `StackingRegressor` | 167 936 |

Все методы поиска используют одну и ту же сетку для данной пары «задача × семейство».
GridSearchCV выполняет полный перебор сетки.
Пространства задаются списками словарей `param_grid`: параметры отключённых шагов и моделей отсутствуют.
Числа в таблице включают выбор обработки признаков. Точный размер зависит от числа признаков задачи.
Ниже указаны имена параметров самих моделей; при реализации добавляются префиксы Pipeline.
`logspace(a, b, n)` означает `numpy.logspace(a, b, n).tolist()`.

### Общие настройки

- Для SVM и MLP оптимизируется Pipeline `scaler → features → model`.
- Для случайного леса и бустинга оптимизируется Pipeline `features → model` без масштабирования.
- Для SVR и MLPRegressor целевая переменная стандартизуется через `TransformedTargetRegressor`.
  Оценки регрессии вычисляются в исходных единицах целевой переменной.
- Все преобразования обучаются только на обучающей части текущего CV-фолда.
- В stacking преобразования находятся внутри Pipeline базовых моделей, а не перед ансамблем.
  Они переобучаются на обучающей части каждого внутреннего фолда stacking.
- У моделей с параметром `random_state` фиксируется значение `0` независимо от seed поискового алгоритма.
- У моделей с параметром `n_jobs` фиксируется `1`; параллельно выполняются пары «задача × семейство».
- Остальные параметры моделей сохраняют значения по умолчанию установленной версии sklearn.

### Обработка признаков

Для SVM и MLP шаг `scaler` принимает одно из четырёх значений:

- `"passthrough"`;
- `StandardScaler()`;
- `RobustScaler()`;
- `MinMaxScaler()`.

Шаг `features` для SVM и MLP выбирается из условных веток:

| Ветка | Параметры |
|---|---|
| `"passthrough"` | Нет |
| `PCA(svd_solver="full")` | `n_components=[0.8, 0.9, 0.95, 0.99]`, `whiten=[False, True]` |
| `SelectKBest` | `k=ceil(p × q)` для `q=[0.25, 0.5, 0.75]`, где `p` — число исходных признаков |

Для `SelectKBest` используется `f_classif` в классификации и `f_regression` в регрессии.
Повторяющиеся значения `k` и варианты `k=p` исключаются.
Для одномерных задач PCA исключается.
Допустимые ветки определяются только числом признаков задачи.
Для леса и бустинга используются только `passthrough` и `SelectKBest`.

### 5. Stacking

| Компонент | Классификация | Регрессия |
|---|---|---|
| Ансамбль | `StackingClassifier` | `StackingRegressor` |
| Базовые модели | SVC, RandomForestClassifier, HistGradientBoostingClassifier | SVR, RandomForestRegressor, HistGradientBoostingRegressor |
| Метамодель | `StandardScaler → LogisticRegression` | `StandardScaler → Ridge` |

В ансамбль включаются любые две базовые модели либо все три: четыре варианта состава.
Имена слотов фиксируются: `svm`, `forest`, `boosting`. Отключённый слот задаётся как `"drop"`.
Для каждого состава создаётся отдельный словарь `param_grid`.

Для базовых моделей перебираются следующие сочетания настроек:

| Слот | Настраиваемые параметры | Фиксированные параметры | Вариантов |
|---|---|---|---:|
| `svm` | Четыре варианта `scaler`; `C=[0.1, 1.0, 10.0, 100.0]`; `gamma=[0.001, 0.01]` | `kernel="rbf"`, `cache_size=200`; у SVC `class_weight=None`, у SVR `epsilon=0.1` | 32 |
| `forest` | `max_depth=[None, 8]`; `min_samples_leaf=[1, 5]`; `max_features=[0.5, 1.0]` | `n_estimators=200`, `bootstrap=True` | 8 |
| `boosting` | `learning_rate=[0.03, 0.1]`; `max_leaf_nodes=[15, 63]`; `l2_regularization=[0.0, 1.0]` | `max_iter=200`, `early_stopping=False` | 8 |

В `svm` масштабирование признаков находится внутри базового Pipeline.
Для SVR стандартизация целевой переменной также находится внутри базовой модели через
`TransformedTargetRegressor` и обучается отдельно на каждом внутреннем фолде.
Дополнительные PCA и отбор признаков в базовых моделях stacking не применяются.

Параметры метамодели:

- Классификация: `LogisticRegression(C=...)`, `C=logspace(-4, 4, 32)`,
  фиксируются `solver="lbfgs"`, `max_iter=2000`.
- Регрессия: `Ridge(alpha=...)`, `alpha=logspace(-5, 5, 32)`.
- Для обеих метамоделей перед моделью стоит `StandardScaler`.
- Для обоих ансамблей оптимизируется `passthrough=[False, True]`.

Для классификации фиксируется `stack_method="auto"`.
Внутренняя CV stacking: три фолда, `shuffle=True`, `random_state=42`;
`StratifiedKFold` для классификации, `KFold` для регрессии. Режим `cv="prefit"` не используется.
Метамодель обучается на предсказаниях внутренних валидационных фолдов.
При `passthrough=True` к ним добавляются исходные признаки текущей обучающей выборки;
их масштабирование выполняется внутри Pipeline метамодели.
Внешняя CV оценивает ансамбль целиком и не заменяется внутренней CV stacking.

Перед запуском рассчитывается и сохраняется точный размер сетки каждой пары «задача × семейство».

## Методы поиска и вычислительные ресурсы

Для каждой из 150 пар «задача × семейство» сравниваются:

1. `GeneticAlgorithm` (GA): все комбинации настроек из раздела ниже.
2. `PDPGA`.
3. `SelfCGA`.
4. `SelfCSHAGA`.
5. `PDPSHAGA`.
6. `SHAGA`: 60 конфигураций.
7. Случайный поиск.
8. Полный `GridSearchCV`.

### Бюджеты

Для эволюционных методов используются восемь отдельных запусков:

```python
[(q, q) for q in range(25, 201, 25)]
```

Первая координата — `pop_size=P`, вторая — `iters=G`:
25×25, 50×50, 75×75, 100×100, 125×125, 150×150, 175×175, 200×200.
Начальная популяция считается первым поколением. Номинальный ресурс запуска `B=P×G`:
от 625 до 40 000 предложений кандидатов.
Досрочная остановка эволюции по стагнации или достижению целевой оценки отключена.
Каждый ресурс запускается независимо, без продолжения предыдущего запуска.

Для случайного поиска `n_iter=min(B, N)`, где `N` — размер пространства текущей задачи и семейства.
Выборка равномерная по всем конфигурациям объединённой сетки, без возвращения.
Для одного seed бюджеты случайного поиска образуют префиксы одной случайной последовательности.
Для каждого бюджета и seed выполняется один случайный поиск, общий для сравнений со всеми
конфигурациями эволюционных методов.

Полный GridSearchCV выполняется первым и один раз для каждой пары «задача × семейство».
Оценки всех конфигураций сохраняются в общем компактном кеше пары. Остальные методы
получают из него только оценки запрошенных кандидатов. Grid включается также при выборе
отдельных методов через `--methods`, поскольку подготавливает общий кеш.

### Все комбинации GA

Запустить декартово произведение пяти селекций, 11 скрещиваний и трёх мутаций.

| Компонент | Варианты | Количество |
|---|---|---:|
| Селекция | `proportional`, `rank`, `tournament_3`, `tournament_5`, `tournament_7` | 5 |
| Скрещивание | Таблица ниже | 11 |
| Мутация | `weak`, `average`, `strong` | 3 |

Скрещивания GA:

| Операторы в коде | Число родителей | Количество |
|---|---|---:|
| `empty` | 1 | 1 |
| `one_point`, `two_point` | 2 | 2 |
| `uniform_2`, `uniform_7` | 2 или 7 | 2 |
| `uniform_prop_2`, `uniform_prop_7` | 2 или 7 | 2 |
| `uniform_rank_2`, `uniform_rank_7` | 2 или 7 | 2 |
| `uniform_tour_3`, `uniform_tour_7` | 3 или 7 | 2 |

Итого: `5 × 11 × 3 = 165` конфигураций GA на каждый бюджет.
Фиксируется `elitism=True`.
Вероятности мутаций берутся из реализации: `1/(3L)`, `1/L`, `3/L`, где `L` — длина генотипа.

### Все комбинации SHAGA

Запустить декартово произведение тех же пяти селекций, что у GA, и 12 скрещиваний:

| Операторы в коде | Дополнительные родители | Всего с текущей особью | Количество |
|---|---:|---:|---:|
| `empty` | 1, результат скрещивания — текущая особь | 1 участвующий | 1 |
| `one_point_1`, `two_point_1` | 1 | 2 | 2 |
| `uniform_1` | 1 | 2 | 1 |
| `uniform_2`, `uniform_7` | 2 или 7 | 3 или 8 | 2 |
| `uniform_prop_2`, `uniform_prop_7` | 2 или 7 | 3 или 8 | 2 |
| `uniform_rank_2`, `uniform_rank_7` | 2 или 7 | 3 или 8 | 2 |
| `uniform_tour_3`, `uniform_tour_7` | 3 или 7 | 4 или 8 | 2 |

Суффиксы операторов задают число дополнительно отобранных родителей.
Итого: `5 × 12 = 60` конфигураций на бюджет, запускаемых через класс `SHAGA`.
Мутация и коэффициент скрещивания адаптируются; их фиксированные значения не перебираются.
`elitism=True` фиксируется. Параметризованные алиасы `*_k` сверх указанного списка не добавляются.

### Адаптивные методы

`PDPGA`, `SelfCGA`, `SelfCSHAGA` и `PDPSHAGA` запускаются по одной конфигурации на бюджет.
Составы пулов операторов, коэффициенты и пороги адаптации берутся из значений по умолчанию
текущей реализации и полностью сохраняются в плане запуска.
Общие настройки: `elitism=True`, одинаковые кодирование, пространство поиска и способ оценки кандидатов.
Настройки адаптации внутри этой серии экспериментов отдельно не подбираются.

### Условия оценки

- Отложенная тестовая выборка — 25%, `random_state=42`; для классификации — стратификация.
- Внешняя CV — три фолда, `shuffle=True`, `random_state=42`:
  `StratifiedKFold` для классификации, `KFold` для регрессии.
- Список seed поисковых алгоритмов фиксируется в плане запуска и одинаков для всех методов.
  Конфигурации разных методов с одним seed образуют сопоставляемые повторения.
  По умолчанию используется seed `42`; список задаётся через `--seeds`.
- Внешние CV-фолды, тестовая выборка, данные и seed ML-моделей одинаковы для всех поисков.
- Критерий оптимизации: `accuracy` для классификации и `neg_root_mean_squared_error` для регрессии.
  RMSE сохраняется также с положительным знаком в исходных единицах целевой переменной.
- Тестовая выборка используется для оценки выбранного по CV кандидата после завершения поиска.
- Известный результат GridSearchCV не используется для управления эволюцией или остановки.
- Кеш CV-оценок общий для методов, бюджетов и поисковых seed внутри одной пары «задача × семейство».
  Данные, CV, метрики и seed моделей фиксированы; номер конфигурации соответствует общей сетке.
  История посещений, повторы и охват учитываются отдельно для каждого поискового запуска.
- Номинальный ресурс, уникальные кандидаты, обучения, попадания в кеш и время учитываются отдельно.
- `cv_fits` и `cv_model_fits` отражают обучения общего кеша, отнесённые к Grid;
  у остальных методов эти счётчики равны нулю. `logical_cv_fits` — число CV-фолдов
  уникальных кандидатов конкретного поиска. `cache_hits` — его собственные повторные предложения.
- `cv_seconds_estimate` суммирует сохранённое время обучения и вычисления метрик
  уникальных кандидатов поиска. Это расчётная работа по CV-фолдам, без поправки на параллелизм;
  она не является измеренным временем независимого запуска. Финальное обучение учитывается отдельно.
- Для GA и SHAGA каждый набор операторов является отдельной конфигурацией эксперимента.
  Сохраняются затраты как отдельной конфигурации, так и всего семейства конфигураций.

### Размер серии

На бюджет и seed — 230 стохастических поисков; на восемь бюджетов — 1 840 на пару.
Общее число запусков при `R` seed: `150 × (1 840 × R + 1)`.

### План запуска

Параметры параллелизма:

- `--jobs N` задаёт максимальное число одновременно выполняемых пар «задача × семейство»;
  по умолчанию `1`.
- `--jobs -1` использует все доступные процессоры.
- Каждая пара выполняется в отдельном процессе с методом запуска `spawn`.
- У CV-оценок, оптимизаторов, ML-моделей и stacking фиксируется `n_jobs=1`.
- Число внутренних потоков BLAS/OpenMP ограничивается единицей в каждом рабочем процессе.
- Внутри пары последовательно выполняются Grid, затем остальные поиски с общим кешем.
  Разные пары выполняются параллельно и не записывают в один кеш.
- Результаты поисков фиксируются в SQLite по завершении каждого запуска;
  общий прогресс и CSV обновляются основным процессом. Журнал пары — `cases/<задача>__<семейство>.log`.
- При остановке сохраняются уже зафиксированные результаты. На Windows и при принудительном
  завершении процесса незаписанная часть текущего пакета CV-фолдов может потребовать повторного обучения.
- Настройки схемы параллелизма сохраняются в manifest, число процессов — в журнале сессий.

До начала вычислений зафиксировать:

- Список поисковых seed.
- Для F1–F17: диапазоны признаков, число объектов, способ генерации, шум и seed генерации.
- Используемое число объектов каждого датасета и правило формирования подвыборки, если она применяется.
- Правило учёта повторных строк при разбиении данных.
- Версии библиотек, значения параметров по умолчанию и настройки параллелизма.
- Сетки, конфигурации оптимизаторов, идентификаторы запусков и полный список заданий.

## Сохраняемые результаты

### Воспроизводимость

- Версии Python и библиотек, commit и состояние исходного кода, параметры оборудования и параллелизма.
- Источник и контрольная сумма каждого датасета; для F1–F17 — диапазоны, число объектов,
  способ генерации, шум и seed; сгенерированные выборки сохраняются.
- Индексы тестовой выборки, внешних CV-фолдов и правила внутренней CV stacking.
- Полная схема Pipeline, сетка, число конфигураций и её контрольная сумма.
- Метод поиска, полный набор его настроек, разрешённые операторы и параметры адаптации,
  seed, `P`, `G`, номинальный ресурс и уникальный идентификатор запуска.
- Seed, доступное состояние генераторов случайных чисел, трасса генотипов и контрольные точки.

### Каждый кандидат

- Идентификатор и хеш декодированной конфигурации; параметры обработки, моделей и ансамбля.
- Порядок и время первого предложения; поколение и позиции повторных предложений.
- Попадания в кеш и идентификатор первоначальной оценки.
- Оценки на обучающей и валидационной частях каждого внешнего CV-фолда, их среднее и разброс.
- Дополнительные метрики: `balanced_accuracy` и `f1_macro` для классификации;
  MAE и R² для регрессии. Они не изменяют выбранную цель оптимизации.
- Время обучения и вычисления метрик по фолдам; ошибки и предупреждения.
- Исходная CV-оценка и fitness, переданный эволюционному алгоритму, с описанием преобразования.

### Ход поиска

- Лучший найденный результат по поколениям, числу предложений, уникальным оценкам и времени.
- По поколениям: генотипы, идентификаторы декодированных кандидатов и fitness популяции.
- Число уникальных генотипов и фенотипов в поколении и накопленный охват пространства.
- Использование операторов и доступные показатели их успешности.
- Для адаптивных методов — вероятности операторов и доступное внутреннее состояние адаптации;
  для SHAGA-производных — значения MR, CR и состояние их адаптации.

### Итог запуска

- Лучшие параметры и CV-оценка, качество выбранной модели на тестовой выборке.
- Реально выполненные поколения, предложения, уникальные оценки, повторы, охват сетки,
  число внешних CV-обучений и финальных переобучений.
- Для stacking отдельно учитываются внутренние обучения базовых моделей и метамодели.
- Время поиска, CV-оценок и финального обучения; статус завершения и причина остановки.

Записи сохраняются постепенно, без накопления всего эксперимента в оперативной памяти.
Завершённые оценки и запуски доступны после прерывания; продолжение использует сохранённое
состояние и не выполняет уже завершённые оценки заново.
Исходные данные и сырые результаты сохраняются до последующей интерпретации.

## Запуск и продолжение

```bash
python experiments/hyperparameter_search/run_experiment.py --jobs 24
```

Скрипт готовит данные, сетки и план, выполняет все поиски и сохраняет результаты в
`experiments/hyperparameter_search/output/experiment/`.
`--smoke` выполняет уменьшенную проверку всех семейств и методов в отдельной папке `output/smoke/`.
`--output` задаёт другую папку результатов.

Отображаются общий прогресс поисков и число активных пар «задача × семейство».
Для каждой активной пары отдельно отображается прогресс Grid: число полностью оценённых
конфигураций, выполненные CV-фолды, скорость, ETA и время с последнего изменения счётчика.
ETA рассчитывается по новым зафиксированным фолдам текущего наблюдения, без учёта уже готового
кеша; до первых измерений показывается `?`. Оценка приблизительная: время конфигураций различается.
Счётчики кеша фиксируются пакетами, поэтому между обновлениями может выполняться обучение.

Для наблюдения за уже запущенным экспериментом из другого терминала:

```bash
python experiments/hyperparameter_search/grid_progress.py --output experiments/hyperparameter_search/output/experiment
```

Монитор открывает кеш только для чтения. Ctrl+C в его терминале завершает только монитор.
Предупреждения и диагностика сохраняются в журналы без вывода в консоль.
Ошибки отдельных поисков сохраняются; остальные задания продолжают выполняться.

Повторная команда пропускает завершённые поиски и использует сохранённые CV-оценки.
Прерванная эволюция воспроизводится с исходного seed и проверкой трассы кандидатов;
сохранённые фолды повторно не обучаются. Незавершённое обучение фолда запускается заново.
Число процессов можно менять при продолжении. Изменение данных, сеток, настроек или кода
требует отдельной папки результатов.

Основные результаты: `summary.csv`, `results.sqlite`, `run.log`.
Данные находятся в `data/`, сетки — в `cases/`, общие CV-оценки — в `cache/`,
журналы отдельных поисков и финальных обучений — в `runs/`.
